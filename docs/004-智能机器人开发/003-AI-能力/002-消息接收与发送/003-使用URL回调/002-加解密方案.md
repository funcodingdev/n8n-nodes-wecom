## 概述

接收 URL 方式下，企业微信与开发者之间的所有回调消息均经过加密处理，被动回复消息也需加密后返回。本文介绍消息的加解密方案，以及具体的签名校验和加解密流程。

企业微信提供了多语言加解密库（C++/Python/PHP/Java/C# 等），开发者可直接使用：[点击下载加解密库](#101776)

> 企业自建智能机器人场景中，加解密库要求传入的 `receiveid` 参数直接传**空字符串**即可。

## 验证 URL 有效性

点击保存提交配置时，企业微信会发送一条验证消息到填写的 URL，请求方式为 **GET**。

> 获取请求参数时需要做 **URL decode** 处理，否则会验证不成功。

**请求示例：**

```
GET https://api.3dept.com/?msg_signature=ASDFQWEXZCVAQFASDFASDFSS&timestamp=13500001234&nonce=123412323&echostr=ENCRYPT_STR
```

**参数说明：**

| 参数 | 必须 | 说明 |
|---|---|---|
| msg_signature | 是 | 企业微信加密签名。将 Token、timestamp、nonce、encrypt 四个参数拼接后进行 sha1 计算得到，与请求中的 msg_signature 对比一致则校验通过 |
| timestamp | 是 | 时间戳 |
| nonce | 是 | 随机数，两小时内保证不重复 |
| echostr | 是 | 加密字符串，需解密后获取明文消息内容 |

**开发者处理步骤：**

1. 对收到的请求参数做 URL decode 处理
2. 通过 `msg_signature` 校验请求签名，确认调用者合法性
3. 解密 `echostr` 得到明文消息内容（即 msg 字段），解密算法参考[企业微信加解密方案说明](#)
4. 在 **1 秒内**响应 GET 请求，响应内容为上一步得到的明文内容（不能加引号，不能带 BOM 头，不能带换行符）

以上 2~3 步可直接使用加解密库提供的 `VerifyURL` 函数一步完成：

```
VerifyURL(sToken, sEncodingAESKey, sReceivedMsgSignature, sReceivedTimestamp, sReceivedNonce, sReceivedEchoStr)
```

| 参数 | 说明 |
|---|---|
| sToken | 配置的 Token |
| sEncodingAESKey | 配置的 Encoding-AESKey |
| sReceivedMsgSignature | 请求中的 msg_signature |
| sReceivedTimestamp | 请求中的 timestamp |
| sReceivedNonce | 请求中的 nonce |
| sReceivedEchoStr | 请求中的 echostr |

返回解密后的明文 msg，直接作为 GET 请求的响应体返回即可。

## 接收回调解密

智能机器人的回调格式为 JSON，企业微信对消息体进行了加密：

**加密数据格式：**

```json
{
 "encrypt": "msg_encrypt"
}
```

**参数说明：**

| 参数 | 是否必填 | 说明 |
|---|---|---|
| encrypt | 是 | 消息结构体加密后的字符串 |

开发者使用加解密库解密 `encrypt` 字段，即可获取事件明文 JSON 报文。完整加解密算法参考[企业微信加解密方案说明](#)。

## 被动回复加密

开发者解密数据得到用户消息内容后，可选择直接回复空包，也可在响应本次请求时直接回复消息。

回复消息需先按[明文协议](#62165)构造 JSON 数据包，再对明文消息进行加密，填入以下协议的 `encrypt` 字段后返回：

**加密数据格式：**

```json
{
 "encrypt": "msg_encrypt",
 "msgsignature": "msg_signature",
 "timestamp": 1641002400,
 "nonce": "nonce"
}
```

**参数说明：**

| 参数 | 是否必须 | 说明 |
|---|---|---|
| encrypt | 是 | 加密后的消息内容 |
| msgsignature | 是 | 消息签名 |
| timestamp | 是 | 时间戳，秒级 |
| nonce | 是 | 随机数，需使用回调 URL 中的 nonce |
